# v2.4.2 Release Logic

## Purpose
v2.4.2 is the stable v2.4 evidence-based personalization build based on the known-good v2.3 architecture.

## User limits
- Daily accepted AI questions: 20 per India calendar day.
- Daily reset: 00:00 IST.
- Burst protection: 5 accepted questions per 10 seconds.
- Daily quota and burst protection are separate controls.

## Rate-limit behavior
- Burst limit exceeded: send the temporary "give me a gap" message.
- Daily limit exceeded: send the explicit daily-quota-complete message.
- Analytics records `burst_limit_reached` separately from `daily_limit_reached`.
- Rate-limited requests do not create an AI job.

## Identity
- Telegram `from.id` is the canonical student identity for analytics and learning-profile data.
- Private-chat operation continues to use the chat ID for message delivery and the existing Durable Object routing.

## v2.4 personalization
- Adds evidence-based `learningSignals` (`confusionCount`, `weakCount`, `lastSeenAt`).
- A single signal does not immediately create a persistent attention topic.
- Repeated explicit confusion/weakness evidence promotes a topic.
- Generic factual questions and simple follow-ups do not invent weakness signals.
- Legacy v2.3 profiles are normalized safely when `learningSignals` is absent.
- Profile persistence errors are best-effort and cannot prevent answer delivery.

## Stability
- v2.3 conversation intelligence and answer-reliability behavior remain the base.
- No D1 schema change.
- Existing Queue, Durable Object, Vertex AI, Telegram and admin architecture is preserved.


## Privileged AI access

The normal account policy is 20 accepted AI questions per India calendar day. A privileged Telegram user is not counted against that daily quota.

A user is privileged when any of these server-side conditions is true:

1. Their Telegram `from.id` matches `BOT_OWNER_TELEGRAM_USER_ID`.
2. Their ID appears in `ADMIN_TELEGRAM_USER_IDS`.
3. Their ID appears in `UNLIMITED_AI_TELEGRAM_USER_IDS`.
4. Their ID has an active row in D1 `ai_access_overrides`.

Privileged users still face the global 5 questions / 10 seconds burst guard. `/reset` does not grant or remove privileged access and does not reset the daily rate metadata.

Admins can grant or revoke runtime unlimited-AI access with `/grant <telegram_user_id>` and `/revoke <telegram_user_id>`. These commands are accepted only from configured admin Telegram IDs.
